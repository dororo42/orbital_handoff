# Handoff Template（交接文档模板与填写指引）

**单一事实源声明**：生成模板的唯一来源是 `scripts/create_handoff.py` 内嵌的 `HANDOFF_TMPL`；本文件是同一模板的**填写指引副本**，直接修改本文件不会改变脚本生成结果。改动模板请改脚本，并同步本文件。

`create_handoff.py` 会把模板预填 git 元数据后生成为 `handoffs/YYYY-MM-DD-HHMMSS-<slug>/HANDOFF.md`（时间戳精确到秒；同一秒内同 slug 会自动加 `-2`、`-3` 后缀，绝不覆盖已有 kit）。「未提交修改」表包含已修改、已暂存与 **untracked 新文件**三类。逐个替换 `[TODO: ...]` 占位符。

填写总原则：

- **具体**：文件路径带行号；命令给完整可执行形态；「改了点东西」不合格，「重构了 `src/api/client.rs:88` 的重试逻辑，从指数退避改为固定 3 次因为上游超时是硬阈值」合格。
- **写 Why 不只写 What**：接手方看代码能看到 What，看不到的是你的决策依据。
- **站在接手方视角**：他没有任何你当前会话的上下文，也没有你的记忆。把他当成「聪明但完全失忆的同事」。
- **绝不写敏感值**：环境变量只写名字不写值，凭证一律脱敏为 `<已脱敏>`。

**写姿势**（多轮交接时每段只能按标注方式修改，防止状态漂移）：

| 段落 | 写姿势 |
|---|---|
| 当前状态摘要 / 未提交修改 | **覆盖写**——永远只反映此刻，新状态替换旧叙述，不追加日志 |
| 决策记录 / 已知坑 / 重要上下文 / 假设 | **追加或取代**——新决策在「为什么选它」注明「取代 \<旧决策\>」；两条矛盾必须删一条或显式标注取代关系 |
| 元数据 / 交接链 / 最近提交 | **仅工具写**——由 create_handoff.py 维护，不要手改 |
| 任务清单 / 立即下一步 / Blocker | **打钩 + 结局标注**——做完打钩写「→ 结局: done \<结果\>」，做不完标 `blocked \<原因\>` |

## 配套件模板（按档位生成）

### RESUME_PROMPT（P 档，`handoffs/<目录>/RESUME_PROMPT.md`）

```markdown
# 接手指令（把本文件全文粘贴给目标 agent 的对话框）

你即将接手一个由另一个 AI agent 移交的开发项目。你们相互隔离，你没有它的任何上下文——所有上下文都在下面的交接文档里。

**项目位置**：[仓库 URL 或本地路径]
**交接文档**：[handoffs/ 目录下 HANDOFF.md 的路径]
**当前分支**：[分支名]

请严格按以下顺序执行，任何一步失败就停下来向用户报告，不要跳步：

1. **读取交接文档**：完整读取上面的 HANDOFF.md（不要只扫标题），如有需要再回溯它引用的前一份交接。
2. **核验环境**：确认你在正确分支上；`git log` 的 HEAD 与文档记录的 HEAD 是否一致；不一致时报告差异并停止。
3. **报告继续计划**：基于文档「立即下一步」第 1 条，给出你的具体执行方案和风险点，等用户确认。
4. **确认后再动代码**：先跑文档里的构建/测试命令验证基线可用，再开始改动。
5. **持续维护交接文档**：完成事项随手打钩并补一行结局（`→ 结局: done <结果> / blocked <原因> / moved <新条目号>`）；尝试过但没做完的条目必须标 `blocked`，不留无结局条目；新发现的坑补进「已知坑」——你也是未来的导出方。

红线：交接文档（handoffs/）永不 commit、永不 push、永不上传；项目代码不要提交/推送，除非用户明说；不要接触 .env、密钥、token；对文档假设与代码现实冲突的地方，以代码现实为准并报告。对 HANDOFF.md **只做加法和打钩**：不重排段落、不改章节标题、不动元数据与交接链——结构整理留给下一次 create_handoff。
```

```markdown
- Branch: [分支] @ [短 SHA]
- Status: [进行中/等待决策/…]

任何 agent 开始工作前，先读上面的 HANDOFF.md。这份指针由 orbital_handoff skill 维护，手工交接时请同步更新。
```
