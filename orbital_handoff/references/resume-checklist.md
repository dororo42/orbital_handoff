# Resume Checklist（接手方核查清单）

RESUME 工作流第 3 步使用。逐项核查，任一项不通过就先向用户报告再决定是否继续。

## 0. 设计不变量（先于一切核查，禁止被后续“优化”掉）

1. **路径不内联**：RESUME 入口（RESUME_PROMPT.md / AGENTS.md 指针段）只含路径与指令，永不内联交接内容——内联即产生第二事实源。反例：把 HANDOFF.md 全文贴进 RESUME_PROMPT，之后 HANDOFF 更新而粘贴件没更新，接手方读到两份矛盾状态。
2. **渲染物一次性**：RESUME_PROMPT.md 是可随时由模板重新生成的一次性快照，不要在其中积累独有信息。
3. **完整读取**：接手方必须完整读取 HANDOFF.md，不许只扫标题。

## 1. 仓库状态与文档对齐

- [ ] 当前分支 = HANDOFF.md 记录的分支
- [ ] `git log -1` 的 HEAD = 文档记录的 HEAD（不一致 → 走新鲜度核验，以仓库为准）
- [ ] 未提交修改清单与文档「未提交修改」一致；多出来的文件先搞清楚是谁改的
- [ ] 交接链完整：文档引用的 `Continues from` 前驱存在

## 2. Blocker 与假设

- [ ] 逐条检查「Blocker / 未决问题」：已被解决的标记并跳过；未解决的保留
- [ ] 逐条验证「假设」仍成立（跑一次相关命令/看一眼相关代码）
- [ ] 「待用户决策」的项没有被用户在新会话里已决策覆盖（看交接文档之后的提交记录）

## 3. 环境可用

- [ ] 文档「构建/运行/测试命令」能跑通（测试基线绿了才动代码）
- [ ] 文档列出的环境变量在本地已配置（只要名字对得上，值不进文档）
- [ ] 工具链版本满足文档要求（若有说明）

## 4. 冲突检测

- [ ] 「关键文件」表格里的文件自交接后未被大幅改动（`git log --oneline <file>` 对照交接时间）
- [ ] 交接文档之后的提交没有实现/推翻「立即下一步」要做的事（避免重复劳动或覆盖）

## 5. 开始工作

- [ ] 输出继续计划（差异报告 + 第一步具体方案 + 风险点），等用户确认
- [ ] 确认后：先跑测试基线 → 执行「立即下一步」第 1 条
- [ ] 工作中持续更新 HANDOFF.md：完成任务打钩并写「→ 结局: done/blocked/moved」；尝试过但没做完的条目必须标 `blocked <原因>`，不留无结局条目
- [ ] **写契约**：对 HANDOFF.md 只做加法和打钩——不重排段落、不改章节标题、不动元数据与交接链；结构整理留给下一次 create_handoff
- [ ] 上一份交接（Continues from）中未打钩的条目，逐条给出交代（done / blocked / moved）；validate 会对缺失交代扣分
- [ ] 本轮结束/上下文吃紧时：主动建议新的 CREATE（接手方即下轮导出方）

## 新鲜度分级对照

| check_staleness.py 输出 | 含义 | 动作 |
|---|---|---|
| FRESH | 交接后几乎无变化 | 直接继续 |
| SLIGHTLY_STALE | 少量提交/文件变化 | 先看新提交再继续 |
| STALE | 明显变化或分支漂移 | 逐项核对假设，报告差异 |
| VERY_STALE | 大量变化或引用文件丢失 | 考虑丢弃旧交接、重建一份 |
